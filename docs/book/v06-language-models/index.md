# Volume VI: Advanced Language Model Architectures

The decoder that Volume V built and trained is the one that started the field, and it is not the one that is run today. Open the weight files of a language model released this year and the tensors are not the ones of that volume's block: the position table is gone, the key and value matrices are narrower than the query matrix, the attention head normalizes its queries and keys before it looks at them, and a layer may not hold attention at all. Every one of those changes was made for a reason that can be counted, in bytes of cache, in operations per token, in memory at a long context or in parameters that a token never touches. This volume takes them one at a time, with the count beside each, and follows one question through all of them: what changed between the first GPT and today's models, and what did each change buy?

The measuring instruments are the ones of the two volumes before. Volume IV taught the reader to price a computation in FLOPs and bytes and to read a device's roofline; Volume V ended with a cache whose size decides how long a context a device can hold and how many people it can serve at once. Almost every architecture idea of this volume is an attack on one of those prices. Sharing keys and values among heads, compressing them into a latent vector, windowing them or selecting a few of them all shrink the cache. Routing each token to a few experts, or replacing attention with a recurrence of fixed size, changes what a token costs in arithmetic. Reusing the same layers several times trades parameters for depth. The volume treats each as a modification of the block of Volume V and asks the same questions of it: what is stored, what is computed, what is lost.

The first two chapters set the ground. The first lays the recipe of a present-day open-weight decoder beside that of GPT-2 and counts what each difference buys; the second shows how to load a checkpoint trained by someone else into one's own implementation and to prove, against reference outputs and to a stated tolerance, that the two compute the same function. Every later chapter relies on both, because the architectures of the later chapters are met as checkpoints, and a variant whose output has not been compared with a reference is a variant that may be quietly wrong. The volume ends with the ledger as a tool: before running a model, count its parameters, its FLOPs per token and its memory, and so know what it will cost.

You can write down the recipe of a modern decoder and say what each of its choices removes or adds in parameters, FLOPs and cache bytes: rotary positions, RMS normalization, a gated feed-forward network, grouped key-value heads, a normalization of queries and keys, a separate output matrix. You can load a published checkpoint through a name mapping into an implementation of your own and state the tolerance within which it reproduces a reference. You can compute the cache of multi-query, grouped, latent and windowed attention, and say what an attention sink is for. You can describe how a router sends each token to a few experts and what keeps the load balanced, how a linear attention carries a state of fixed size instead of a cache that grows, how a model can select the few positions it reads, and what happens when the same layers are applied several times. You can say how a model trained on short texts is made to read long ones. You can count the parameters, the FLOPs per token and the inference and training memory of any of these before running it, and judge a research architecture by the experiments that would show it wrong. The project that ends the volume implements several alternative blocks and compares their quality, cost and memory on equal terms.

2. [Importing Pretrained Models and Proving Parity](02-importing-models.md): how to load someone else's trained weights into your own implementation and prove it computes the same thing.
3. [Attention Variants: Sharing and Compressing Keys](03-attention-variants.md): how to shrink the KV cache without losing what attention needs.

5. [Linear Attention, Recurrence and Hybrid Models](05-linear-attention.md): whether attention can be computed in time linear in the sequence length, and what is lost.
6. [Sparse Attention](06-sparse-attention.md): how to find the few tokens that each token needs, cheaply.
7. [Looped and Recurrent-Depth Transformers](07-recurrent-depth.md): what happens when a model thinks longer by reusing the same layers more times.
8. [Long Context](08-long-context.md): how models trained on short texts read long ones.
9. [A Research Architecture: The Spectral Language Model](09-spectral-lm.md): how to test a new architectural idea honestly, using brain's spectral language model as the example.
10. [Counting Parameters, FLOPs and Memory](10-model-cost.md): how to know, before running a model, what it will cost.
11. [Project: Comparing Language Model Blocks](11-project-architecture-comparison.md): implement several alternative language-model blocks and compare their quality, cost and memory fairly.

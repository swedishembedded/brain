# Volume XV: Scientific and Engineering Methods

Everything the earlier volumes built rests on claims: that a port computes what its reference computes, that a test which passes has checked something, that a kernel is faster than the one it replaced, that an architecture learns better than another. Each claim is made by running a program and reading a number, and each can be wrong in a way the number does not show. A comparison against the wrong reference agrees perfectly. A test that never ran reports success. A benchmark that timed the host while the device was still working reports a speed nobody will see. A result that held on one seed is printed as if it held on all of them. None of these is a mistake in the mathematics the book has taught; they are mistakes in the method by which the mathematics is checked, and they are the ones that survive longest, because every tool built to catch mistakes is built on the method.

This volume is about that method, the discipline that turns a running program into evidence. It starts where most of the book's case study started, with a model published by someone else and a reimplementation that has to be proved equal to it: how the comparison is arranged so that every mistake is located, how the reference outputs are generated so that they can see what they are meant to see, and in what order the steps of a port are taken. It turns to the tests of numerical code in general and to the ways they pass while the code is wrong, from dimensions that hide a confusion of two sizes to a metric that cannot see a scale and a gate that never runs. It takes up performance claims, what makes a measurement trustworthy and the classic ways a benchmark lies, with speed stated as work done against what the device can do. It follows an idea from a hypothesis that could be refuted to a result others can rerun, check and build on. And it closes with a catalogue of real failures from building an engine, each traced to its root cause and to the gate that now stops it from coming back.

The volume comes this late because it needs everything before it as material. The rounding model of Volume I is what a tolerance is derived from, the gradient check of Volume III is the first proof of a backward pass, the roofline of Volume IV is what a benchmark is held against, the import and parity of Volume VI are the first proof of a forward pass, and the training and serving machinery of Volumes XIII and XIV is what most of the catalogued failures happened in. The chapters here do not add a new kind of model. They take the methods that appeared chapter by chapter as needed and state them as a discipline of their own, with the reasons that make each step necessary.

After it you can take a published model to a proven reimplementation step by step, comparing every stage both on the reference's own inputs and on your own outputs, and say which mistakes a given set of reference outputs can and cannot see. You can generate reference outputs that are reproducible and tied to the checkpoint they came from, and keep forward parity and gradient checking apart as the two different proofs they are. The later chapters add the rest: to write numerical tests that cannot be fooled, to make and defend a performance claim, to carry a hypothesis to a result others can reproduce, and to turn each expensive mistake into a gate that keeps it from recurring. The volume ends with a project that does all of it at once on one published component.

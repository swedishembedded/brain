# T5-XXL encoder (`crates/t5`) — status ledger

Chronological, measured-only. This crate exists because **FLUX.1 conditions on
T5-XXL**; it is an encoder-only port with no decoder, no LM head and no
tokenizer.

## P0–P1 (2026-08) — goldens, import, forward parity

Goldens: `tools/goldens/t5_dump_reference.py`, per-stage via forward hooks on
`transformers.T5EncoderModel`. Fixtures under `testdata/t5/` (gitignored).

- **Import**: 219 source tensors → **171 parameters**, two-way covered —
  `validate` proves set equality (every manifest name present *and*
  `map.len() == manifest.len()`), shapes and data lengths are both checked,
  unrecognised source names are rejected by name, and duplicate mappings and
  incomplete q/k/v sets are errors. There is no zero-fill path.
- A duplicated `encoder.embed_tokens.weight` is **rejected** as an unrecognized
  tensor rather than silently ignored — deliberate, because nothing checks that
  it equals `shared.weight`. (`T5EncoderModel.state_dict()` does carry it as an
  alias; safetensors refuses to serialise the aliased pair, which is why the
  released checkpoint has 219 tensors and only `shared.weight`.)
- `relative_position_bucket`: **16384 entries, exact** vs the reference.

### Forward parity — measured (Tesla P40, `BRAIN_DEVICE=gpu0`, `--release`)

`BRAIN_T5_XXL` = the Kontext `text_encoder_2`. **B=2, T=128.**

- **42 stages checked, 0 failed, worst cosine 0.9999999992.**
- `position_bias` and `embed`: max_abs **0.000e0**.
- `block23_out` 0.9999999992 / max_abs 3.271e0 / relL2 4.048e-5. The absolute
  number is large because the *stage* is: measured directly from the golden,
  `block23_out` has max|x| **2.3613e5** and rms **1184.8**, so 3.271 is 1.4e-5
  of peak. Scale, not drift.
- `last_hidden_state` 0.9999999996 / 9.284e-4 / 2.831e-5;
  `last_hidden_state[content]` **1.0000000000** / 2.694e-5 / 6.116e-6.

### The dimensional-coverage hole, and the gate that closes it

At T5-XXL, `heads == d_kv == 64` **and** `heads·d_kv == d_model == 4096`. A port
that confused the head count with the head width, or `d_model` with the
attention inner width, would pass the 19 GB gate at cosine 1.0. `tests/tiny_ref.rs`
closes it: a **checkpoint-free** replay of a random 2-layer torch
`T5EncoderModel` at `heads=2, d_kv=64, d_model=64` (so `inner=128 ≠ d_model` and
`heads ≠ d_kv`), regenerated by `tools/goldens/t5_dump_reference.py` with no `--model`.
**17 stages, cosine 1.0000000000 on all of them.**

## Deferred — explicitly NOT done

* **T=512**, the length FLUX.1 actually uses. Gated at T=128 only. fp32 at
  T=512 does not fit one 24 GiB card (activations ≈7.5 GB, total >26 GB), and
  the score-slab dispatch there is 33.5 M threads = 524 288 workgroups, past the
  65 535 per-dimension limit — so it takes the kernels' **2D-grid path, which
  T=128 never exercises**. Check that first.
* **Backward / gradcheck.** `scores` and `probs` are the only non-SSA buffers
  (8.4 MB each at T=128, 134 MB at T=512), and q/k/v are fused `[3·inner,
  d_model]` at row offsets `0 / inner / 2·inner`. An FD oracle must be built at
  the **`tiny_ref` dims, not XXL's** — at XXL a gradient oracle that confuses
  `heads` with `d_kv` would agree with a wrong backward for exactly the reason
  above.
* **Serving contract**: no `Provider`, no residency adapter, no `run_batch`, no
  D-Bus, no CLI subcommand. `crates/flux1` declares `brain-t5` as a dependency
  but does not yet call it.
* **Tokenizer**: not implemented. The parity test replays reference input ids.
* **CPU-JIT leg**: `backend-cpu` runs green, but its reduction order depends on
  rayon splitting, so its low digits are not a fingerprint.

# S3Tokenizer (speech tokenizer, component)

The supervised-semantic FSQ speech tokenizer [CosyVoice](cosyvoice.md)
conditions its LM on - turns 16 kHz reference audio into 25 Hz FSQ token ids
(`3^8 = 6561` codes) for zero-shot voice cloning. Two codebook versions, v2
(CosyVoice 2) and v3 (CosyVoice 3), sharing the same codebook size. Not
independently servable: it has no capability manifest or CLI verb of its own,
reached only as part of CosyVoice's own actions.

## Status

**v2 done**: `speech_tokenizer_v2.onnx` (`AudioEncoderV2` - RoPE + FSMN
multi-head attention, 6 layers, `n_audio_state 1280`, `n_audio_head 20` - plus
the FSQ head) is imported (`s3tokenizer::import`) and run
(`s3tokenizer::model::forward`) as pure host f32 math, gated on **exact
integer token-id equality** against a real ONNX reference dump (these are
codebook indices, not a continuous quantity - cosine similarity cannot gate
them; `crates/s3tokenizer/tests/s3tokenizer_parity.rs`, regenerated by
`tools/goldens/cosyvoice_dump_reference.py`). All 87 tokens of the real
reference clip match exactly.

**v3 is a deliberate, recorded gap.** `speech_tokenizer_v3.onnx` uses a
12-layer MinMo encoder, not a straightforward `n_audio_layer: 12` on the same
`AudioEncoderV2` - CosyVoice 3's release describes a different encoder
backbone. It has not been read, imported, or config-modeled. Adding it is a
follow-up milestone (new `S3TokenizerConfig` variant + import schedule), not
a flag on `S3TokenizerConfig::v2()`.

Weights env vars, one per codebook version: `BRAIN_S3TOKENIZER_V2` (read by
the parity test today), `BRAIN_S3TOKENIZER_V3` (reserved, unused until v3
lands).

Package: `brain-s3tokenizer`.

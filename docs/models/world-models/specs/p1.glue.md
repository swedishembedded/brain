## 1. Purpose

Nine small "glue" kernels the world-model stack (DIAMOND EDM denoiser,
GenieRedux, iVideoGPT) composes around the existing conv/attention/norm
kernels:

- `mul` — generic elementwise Hadamard product (GEGLU tail, gradient
  compositions).
- `scale_row` — per-sample (per-row) scalar scale, e.g. EDM `c_in(sigma)`
  applied to a noised sample.
- `edm_mix` — the EDM output skip `D = c_skip*x + c_out*F(...)` in one pass.
- `mse_value_w` / `mse_grad_w` — per-sample-weighted MSE loss value and
  gradient (EDM `lambda(sigma)` loss weighting).
- `pad2d` / `crop2d` — asymmetric zero-padding on NCHW and its exact adjoint
  (UNet odd-size alignment; each is the other's backward).
- `nchw_nlc` / `nlc_nchw` — NCHW ↔ `[N, L=H*W, C]` layout permutation
  (conv stack ↔ transformer/attention stack); mutual inverses AND mutual
  adjoints.

All kernels: fp32 only, uniform `Params` at `@group(0) @binding(0)`, ≤ 4
storage buffers, `@workgroup_size(64)`, no atomics / barriers / f16, no f32
`%` (u32 `%` and `/` are fine), single-source (no per-backend forks),
2D-grid-safe linear thread index
`gidx = gid.y * (nwg.x * 64u) + gid.x` (identity for 1D dispatch).

This unit is kernel-text only (crate `brain-kernels` is pure string data).
There is NO new host wrapper crate: the public surface is the nine
registered kernel constants (§8); dispatch sites call `gpu.step` directly
with the parameter tables of §8.

## 2. Shapes, layouts, index conventions

Row-major throughout.

- Flat vectors `[n]`: `mul` treats all operands as flat length-`n` arrays.
- Row-major 2D `[N, M]` ("N samples × M elements per sample"): flat index
  `i = n*M + m`, so `n = i / M` (u32 division), `m = i % M`. Used by
  `scale_row`, `edm_mix`, `mse_value_w`, `mse_grad_w`. The caller flattens
  NCHW batches as `M = C*H*W`.
- NCHW `x[N, C, H, W]`: `idx(n,c,h,w) = ((n*C + c)*H + h)*W + w`.
  `pad2d`/`crop2d` never need `n` and `c` separately — only the combined
  image index `p = n*C + c`, recovered as `p = idx / (H*W)` for the
  respective tensor's `H, W`.
- NLC `[N, L, C]` with `L = H*W`, `l = h*W + w`:
  `idx(n,l,c) = (n*L + l)*C + c`.
- `pad2d`/`crop2d` params carry the SMALL (unpadded/cropped) spatial dims
  `h, w` plus the four pad amounts `l, r, t, b` (left/right/top/bottom,
  u32, may each be 0). Padded dims are always derived in-kernel:
  `hp = h + t + b`, `wp = w + l + r`.
- All layout/copy kernels (pad2d interior, crop2d, nchw_nlc, nlc_nchw) are
  GATHERS: one thread per OUTPUT element reads exactly one input element
  (or writes literal `0.0`). Never scatter.
- f32 values in uniforms use the `gpu_core::f` convention (host passes
  `f32::to_bits`, kernel reads `bitcast<f32>(p.field)`).

Host-side contracts (kernels ASSUME them; violations are caller bugs, not
kernel-detectable):

- `mul`: `len(a) == len(b) == len(y) == n`.
- `[N, M]` kernels: buffer length `== N*M`, `M >= 1`, `N >= 1`.
- `pad2d`: `len(x) == NC*h*w`, `len(y) == NC*(h+t+b)*(w+l+r)`,
  `total == len(y)`.
- `crop2d`: `len(x) == NC*(h+t+b)*(w+l+r)`, `len(y) == NC*h*w`,
  `total == len(y)` — i.e. `h, w` are the OUTPUT dims and the input is the
  padded tensor. Cropping "more than available" is unrepresentable: the
  input is by contract exactly the padded shape.
- `nchw_nlc`/`nlc_nchw`: `total == N*hw*c` = length of both buffers.

## 3. Math

### 3.1 mul

```
y[i] = a[i] * b[i]                      i in [0, n)
```

Backward COMPOSES from the same kernel — no new kernel:

```
da = mul(dy, b)         db = mul(dy, a)
```

GEGLU (documented decision — no fused kernel): with a channel-split
`(u, v)`, `GEGLU(u, v) = gelu(u) ⊙ v`. Forward = existing `gelu` (tanh
approximation, `crates/kernels/wgsl/gelu.wgsl`) into a fresh SSA buffer
`gu`, then `mul(gu, v)`. Backward: `dv = mul(dy, gu)` (reads the cached
`gu`), `du = gelu_bwd(u, mul(dy, v))`. Reusing `gelu`/`gelu_bwd` + `mul`
keeps one gradient source of truth; a fused `geglu` would need its own bwd
pair for zero measured benefit at wm sizes.

### 3.2 scale_row

`x[N, M]`, `s[N]`:

```
y[n*M + m] = s[n] * x[n*M + m]          i.e.  y[i] = s[i / M] * x[i]
```

Backward w.r.t. x (diagonal, hence self-adjoint per row):

```
dx = scale_row(dy, s)
```

`ds` is deliberately NOT provided (documented decision): every wm use of
`scale_row` applies EDM `c_in/c_skip/c_out/lambda(sigma)` factors, which
are deterministic functions of the sampled noise level `sigma` — constants
of the graph, not trained parameters. No gradient ever flows into `s`. If
a future model trains through a per-row scale, the `ds` row-reduction
kernel becomes its own TDD unit.

Relation to the existing `scale_chan` (`out[i] = x[i]*scale[(i/inner)%c]`):
`scale_row` is the `[N, M]` special case where `i/M < N` always, so the `%`
is dead. A dedicated kernel keeps EDM dispatch sites self-documenting and
drops the modulo from the hot path; the semantics at `inner=M, c=N` are
identical (a test may exploit this as a cross-check but is not required).

### 3.3 edm_mix

`x[N, M]`, `f[N, M]`, `ab[N, 2]` packed `ab[2n] = a[n]`, `ab[2n+1] = b[n]`:

```
y[i] = a[n] * x[i] + b[n] * f[i]        n = i / M
```

EDM reading: `x` = noised input, `f` = network output,
`a = c_skip(sigma)`, `b = c_out(sigma)`, `y = D(x; sigma)`. Packing a and b
into one `[N,2]` buffer keeps the kernel at exactly 4 storage buffers.

Backward w.r.t. x and f (a, b are sigma-derived constants — same decision
as §3.2, no `dab` kernel):

```
dx = scale_row(dy, a_vec)       df = scale_row(dy, b_vec)
```

The host keeps the unpacked `a_vec[N]`, `b_vec[N]` it computed from sigma
before packing `ab`; it does not unpack on the GPU.

Identity property (required test §6.3): `a[n] = 1.0`, `b[n] = 0.0` for all
n gives `y[i] = 1.0*x[i] + 0.0*f[i] == x[i]` exactly in f32 for all finite
`x`, `f` (`1.0*x` is exact; `0.0*f` is a signed zero; `x + ±0.0 == x`).
Assert exact f32 equality `==` (NOT bitwise: `x = -0.0` yields `+0.0`).

### 3.4 mse_value_w — per-sample weighted MSE partial sums

`pred[N, M]`, `tgt[N, M]`, `w[N]`:

```
out[n] = w[n] * ( Σ_{m=0}^{M-1} (pred[n*M+m] - tgt[n*M+m])^2 ) / M
```

Reduction convention MIRRORS `mse_value.wgsl` exactly: the kernel divides
by the per-thread element count `M` so the host-side reduction stays a
PLAIN SUM, and the grad kernel (§3.5) divides by the SAME `M`. Host loss:

```
L = scale * Σ_{n=0}^{N-1} out[n]
```

where `scale` is whatever upstream factor the caller wants (e.g. `1/N` for
a batch mean, or 1.0). `scale` lives in the GRAD kernel's params (§3.5) and
on the host for the value; it is deliberately NOT in `mse_value_w` so the
partial sums stay per-sample-interpretable (logging per-sample loss).

One thread per SAMPLE `n` (N threads), sequential loop over the sample's
`M` elements in ascending `m` order — the determinism contract (§10).

`dtgt` is not provided: targets are data.

### 3.5 mse_grad_w

Exact gradient of `L = scale * Σ_n out[n]` w.r.t. `pred`, one thread per
element (`N*M` threads):

```
dpred[i] = w[n] * 2 * (pred[i] - tgt[i]) / M * scale        n = i / M
```

`scale` is an f32 passed as bits in params (upstream scale, e.g. `1/N`).
Derivation: `∂L/∂pred[i] = scale * w[n] * ∂/∂pred[i] [ (1/M) Σ_m d_m² ]
= scale * w[n] * 2 d_i / M`.

### 3.6 pad2d

Input `x[NC, h, w]` (NC = N*C combined), output `y[NC, hp, wp]`,
`hp = h+t+b`, `wp = w+l+r`. One thread per OUTPUT element `idx`:

```
p  = idx / (hp*wp)
r0 = idx % (hp*wp)          // u32 %
ho = r0 / wp
wo = r0 % wp
inside = (ho >= t) && (ho < t + h) && (wo >= l) && (wo < l + w)
y[idx] = inside ? x[p*h*w + (ho - t)*w + (wo - l)] : 0.0
```

As a linear map `y = P x`, `P` is the injection of the interior; its
transpose is exactly `crop2d` with the same `(l,r,t,b)`.
Backward: `dx = crop2d(dy)` (same offsets).

### 3.7 crop2d

Input `x[NC, hp, wp]` (the PADDED tensor), output `y[NC, h, w]`. One
thread per OUTPUT element `idx`:

```
p  = idx / (h*w)
r0 = idx % (h*w)
ho = r0 / w
wo = r0 % w
y[idx] = x[p*hp*wp + (ho + t)*wp + (wo + l)]
```

`crop2d = pad2dᵀ` (it discards exactly what pad2d zero-fills). Backward:
`dx = pad2d(dy)` (same offsets). Required adjointness property (§6.1):
for all x (unpadded shape) and y (padded shape),
`⟨pad2d(x), y⟩ == ⟨x, crop2d(y)⟩`, and `crop2d(pad2d(x)) == x` bitwise
(the interior is a bit-exact copy).

### 3.8 nchw_nlc

`x` NCHW `[N, C, hw]` (spatial flattened, `hw = H*W`), `y` NLC
`[N, hw, C]`. One thread per OUTPUT element:

```
n  = idx / (hw*c)
r0 = idx % (hw*c)
l  = r0 / c
ch = r0 % c
y[idx] = x[(n*c + ch)*hw + l]
```

### 3.9 nlc_nchw

Exact inverse: `x` NLC `[N, hw, C]`, `y` NCHW `[N, C, hw]`. One thread per
OUTPUT element:

```
n  = idx / (c*hw)
r0 = idx % (c*hw)
ch = r0 / hw
l  = r0 % hw
y[idx] = x[(n*hw + l)*c + ch]
```

Both are permutation matrices (orthogonal), so
`inverse == transpose == adjoint`:
`nlc_nchw(nchw_nlc(x)) == x` BITWISE, and
`⟨nchw_nlc(x), y⟩ == ⟨x, nlc_nchw(y)⟩` for all x, y (required, §6.2).
Backward of `nchw_nlc` is `nlc_nchw` and vice versa.

## 4. Kernel contracts

Common: `@workgroup_size(64)`, index
`gidx = gid.y * (nwg.x * 64u) + gid.x`, bounds-check `>= total` (or `>= n`)
and return. Uniform `Params` at `@group(0) @binding(0)`; storage buffers
from `@binding(1)` in the listed order; last buffer is `read_write`, the
rest `read`. Every output element is OVERWRITTEN (no accumulation) — SSA
convention, callers accumulate separately if needed.

### 4.1 `mul` — `n` threads

```
Params { n: u32 }
b1 a : read   [n]
b2 b : read   [n]
b3 y : read_write [n]
```

`y[i] = a[i] * b[i]`.

### 4.2 `scale_row` — `total` threads

```
Params { total: u32, m: u32 }
b1 x : read   [total]        // [N, M] row-major, total = N*M
b2 s : read   [N]
b3 y : read_write [total]
```

`y[i] = s[i / m] * x[i]`.

### 4.3 `edm_mix` — `total` threads

```
Params { total: u32, m: u32 }
b1 x  : read   [total]       // [N, M]
b2 f  : read   [total]       // [N, M]
b3 ab : read   [2N]          // ab[2n]=a[n], ab[2n+1]=b[n]
b4 y  : read_write [total]
```

`n = i / m; y[i] = ab[2n] * x[i] + ab[2n+1] * f[i]`.

### 4.4 `mse_value_w` — `n` threads (one per SAMPLE)

```
Params { n: u32, m: u32 }    // n = samples N, m = elems per sample M
b1 pred : read   [n*m]
b2 tgt  : read   [n*m]
b3 w    : read   [n]
b4 out  : read_write [n]
```

Thread `k < n`: sequential loop `j = 0..m` ascending over
`i = k*m + j`, `acc += (pred[i]-tgt[i])^2`; then
`out[k] = w[k] * acc / f32(m)`. Division ONCE at the end (not per
element) — with `acc` accumulated in ascending-j order this is the
determinism contract; mirrors `mse_value`'s divide-inside-kernel,
host-plain-sum convention.

### 4.5 `mse_grad_w` — `total` threads (one per ELEMENT)

```
Params { total: u32, m: u32, scale: u32 /* bitcast<f32> */ }
b1 pred  : read   [total]
b2 tgt   : read   [total]
b3 w     : read   [N]        // N = total/m
b4 dpred : read_write [total]
```

`n = i / m; dpred[i] = w[n] * 2.0 * (pred[i]-tgt[i]) / f32(m) *
bitcast<f32>(scale)`.

### 4.6 `pad2d` — `total` threads (one per OUTPUT element)

```
Params { total: u32, h: u32, w: u32, l: u32, r: u32, t: u32, b: u32 }
b1 x : read        [NC*h*w]                  // unpadded input
b2 y : read_write  [total] = [NC*(h+t+b)*(w+l+r)]
```

§3.6. Zeros written explicitly (every output element written exactly
once).

### 4.7 `crop2d` — `total` threads (one per OUTPUT element)

```
Params { total: u32, h: u32, w: u32, l: u32, r: u32, t: u32, b: u32 }
b1 x : read        [NC*(h+t+b)*(w+l+r)]      // padded input
b2 y : read_write  [total] = [NC*h*w]
```

§3.7. Identical `Params` layout to `pad2d` (same host params array works
for the adjoint pair up to `total`).

### 4.8 `nchw_nlc` — `total` threads

```
Params { total: u32, c: u32, hw: u32 }
b1 x : read        [total]   // NCHW
b2 y : read_write  [total]   // NLC
```

§3.8.

### 4.9 `nlc_nchw` — `total` threads

```
Params { total: u32, c: u32, hw: u32 }
b1 x : read        [total]   // NLC
b2 y : read_write  [total]   // NCHW
```

§3.9.

## 6. Required properties (beyond the point references)

1. **pad/crop adjointness** — random tiny tensors (LCG-seeded, values in
   [−1,1]), shapes incl. `NC=2, h=3, w=2` with offsets
   `(l,r,t,b) ∈ {(1,2,0,1), (0,0,0,0), (2,0,3,0)}`:
   `|⟨pad2d(x), y⟩ − ⟨x, crop2d(y)⟩| ≤ 1e-5` (host f32 dot, same
   ascending-index summation order on both sides). With `(0,0,0,0)` both
   kernels must be bitwise identity copies.
2. **NCHW↔NLC roundtrip + adjointness** — random tiny `N=2, C=3, hw=4`:
   `nlc_nchw(nchw_nlc(x))` BITWISE equal to `x`; adjointness as in 1
   (`≤ 1e-5`).
3. **edm_mix skip-identity** — `a_vec = 1.0`, `b_vec = 0.0` (packed
   `ab = [1,0,1,0,...]`), random finite x, f: `y[i] == x[i]` exact f32
   equality (`==`, not bitwise — §3.3 signed-zero caveat).
4. **crop∘pad identity** — `crop2d(pad2d(x))` bitwise equal to `x` for a
   random tiny tensor and asymmetric offsets.
5. **FD gradient: mse_grad_w vs mse_value_w** — §9 test 7; this is the
   unit's REQUIRED GRADCHECK ENTRY (kernel-level, `mse_fd.rs` pattern —
   NOT a CheckModel registration; nothing trainable here).

## 7. Edge cases

- `M = 1` (`scale_row`, `edm_mix`, mse pair): per-element weights;
  `n = i`. Must work (covered by FD shape if convenient; no separate test
  required).
- `w[n] = 0`: sample contributes exactly `0.0` to loss and gradient.
- Zero pad offsets (`l=r=t=b=0`): `pad2d` and `crop2d` are bitwise identity
  copies (required in §6.1).
- Pads are u32: negative padding is unrepresentable by design; "crop more
  than available" is impossible under the §2 shape contract (input to
  `crop2d` is exactly the padded shape).
- `hw = 1` or `C = 1`: NCHW↔NLC degenerate to copies; no special casing in
  the kernel (the general index math already yields identity).
- Non-finite inputs (inf/NaN): undefined behavior by contract (e.g.
  `0.0 * inf = NaN` would break §6.3); all wm inputs are finite.
- `mse_value_w` divides by `f32(m)` ONCE after the loop (not per element):
  keeps the sum exact for exact inputs and is the convention tests assume.
- Buffer-length mismatches are host bugs (out-of-bounds reads are clamped
  by WGSL runtime semantics but produce garbage — unreachable under §2
  contracts).

## 8. API surface, registration, dispatch tables

New public surface = nine `pub const` kernel strings in `brain-kernels`
(`kernels::MUL`, `SCALE_ROW`, `EDM_MIX`, `MSE_VALUE_W`, `MSE_GRAD_W`,
`PAD2D`, `CROP2D`, `NCHW_NLC`, `NLC_NCHW`) plus their `ALL` registry
entries — GENERATED by `make kernels-regen` (never hand-edited). There is
no Rust wrapper in this unit; `crates/kernels` is pure string data, so the
"stubs" are compile-valid placeholder kernels (contract header + zero
writes) that let tests compile and fail at runtime.

Dispatch (`gpu.step(kind, bufs, params, threads)`, `f = gpu_core::f`,
`N*M = total`):

| kernel        | buffers (in order)        | params                          | threads      |
|---------------|---------------------------|---------------------------------|--------------|
| `mul`         | `[a, b, y]`               | `[n]`                           | `n`          |
| `scale_row`   | `[x, s, y]`               | `[total, m]`                    | `total`      |
| `edm_mix`     | `[x, f, ab, y]`           | `[total, m]`                    | `total`      |
| `mse_value_w` | `[pred, tgt, w, out]`     | `[n, m]`                        | `n` (samples)|
| `mse_grad_w`  | `[pred, tgt, w, dpred]`   | `[total, m, f(scale)]`          | `total`      |
| `pad2d`       | `[x, y]`                  | `[total_out, h, w, l, r, t, b]` | `total_out`  |
| `crop2d`      | `[x, y]`                  | `[total_out, h, w, l, r, t, b]` | `total_out`  |
| `nchw_nlc`    | `[x, y]`                  | `[total, c, hw]`                | `total`      |
| `nlc_nchw`    | `[x, y]`                  | `[total, c, hw]`                | `total`      |

Backward composition summary (no new kernels anywhere):

| forward        | backward                                                  |
|----------------|-----------------------------------------------------------|
| `mul(a,b)`     | `da = mul(dy,b)`, `db = mul(dy,a)`                        |
| `scale_row`    | `dx = scale_row(dy,s)`; no `ds` (§3.2)                    |
| `edm_mix`      | `dx = scale_row(dy,a_vec)`, `df = scale_row(dy,b_vec)`; no `dab` (§3.3) |
| `mse_value_w`  | `mse_grad_w` (§3.5); no `dtgt`, no `dw`                   |
| `pad2d`        | `dx = crop2d(dy)` same offsets                            |
| `crop2d`       | `dx = pad2d(dy)` same offsets                             |
| `nchw_nlc`     | `dx = nlc_nchw(dy)`                                       |
| `nlc_nchw`     | `dx = nchw_nlc(dy)`                                       |

## 10. Determinism

- Every output element of every kernel is written by exactly ONE thread;
  no atomics, no barriers, no workgroup memory, gather-only layout kernels
  → no data races by construction.
- The only reduction in the unit is `mse_value_w`'s per-thread sequential
  loop, in FIXED ascending element order with a single division at the
  end; fp32 summation order is identical on every run →
  bitwise-reproducible on a given backend (test §9.13 enforces on the CPU
  backend).
- Layout kernels (`pad2d` interior, `crop2d`, `nchw_nlc`, `nlc_nchw`) are
  pure copies: outputs are bit-exact images of inputs (asserted bitwise in
  §9.8/9/11/12).
- Cross-backend (CPU vs wgpu/Vulkan) parity: tolerance-level only for the
  arithmetic kernels (fma contraction may differ), bit-exact for the pure
  copy kernels; gating is CPU-only regardless.

## 11. Acceptance criteria

1. All nine `.wgsl` files exist and are registered via `make kernels-regen`
   (sorted const block + `ALL`), and JIT-compile on the CPU backend
   (`wgsl-cpu` `compile_all` passes — no playbook-§2 constructs; in
   particular no f32 `%`, u32 `%`/`/` only).
2. Kernel invariants hold for all nine: uniform `Params` at binding 0, ≤ 4
   storage buffers (`edm_mix`, `mse_value_w`, `mse_grad_w` are exactly 4),
   `@workgroup_size(64)`, fp32 only, no atomics/barriers/f16, 2D-grid-safe
   index, single-source. `scale` appears ONLY in `mse_grad_w`, via
   `bitcast<f32>`.
3. No new Rust API and no new crate: the public surface is exactly the
   nine generated `kernels::` consts + `ALL` entries.
4. All §9 tests pass with `BRAIN_DEVICE=cpu` under
   `scripts/wm-locked-make.sh` (red first, then green after implement);
   full `gate` (build + test + gradcheck) green.
5. No test weakened: tolerances exactly as specified (1e-6 arithmetic
   refs, bitwise for copies/roundtrip/determinism, exact `==` for the
   edm_mix identity, global FD tolerances for §9.7 with the nonzero-loss
   guard intact).
6. Backward everywhere is COMPOSITION per §8's table — the diff introduces
   no `mul_bwd`/`pad2d_bwd`/`ds`/`dab`-style kernels.
7. Documented decisions present in kernel headers: GEGLU = `gelu` then
   `mul` (§3.1); no `ds`/`dab` because EDM `c_*`/`lambda` are
   sigma-derived constants, not trained (§3.2–3.3); `mse_value_w` mirrors
   `mse_value`'s divide-in-kernel + host-plain-sum reduction convention
   (§3.4).

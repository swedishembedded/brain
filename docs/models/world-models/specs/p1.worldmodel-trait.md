## 2. API signatures (exact)

```rust
/// A playable world model: reset with context, then step one action at a
/// time, receiving one frame per step.
///
/// Frames are CHW-ordered `f32` in `[0, 1]`:
/// `frame[c*H*W + y*W + x]` with `(C, H, W) = frame_shape()`,
/// `c in 0..C` (channel), `y in 0..H` (row, top = 0), `x in 0..W` (column,
/// left = 0). Every `step` returns a `Vec<f32>` of length exactly `C*H*W`.
pub trait WorldModel {
    /// (C, H, W) of every frame this model consumes and produces.
    fn frame_shape(&self) -> (u32, u32, u32);
    /// Number of discrete actions; valid actions are `0..num_actions()`.
    fn num_actions(&self) -> u32;
    /// Re-seed the model from context frames (concatenated CHW frames, may
    /// be empty) and context actions (may be empty). Deterministic: the same
    /// `(ctx_frames, ctx_actions)` bytes always produce the same state.
    fn reset(&mut self, ctx_frames: &[f32], ctx_actions: &[u32]);
    /// Advance one step with `action` (must be `< num_actions()`) and return
    /// the next frame, CHW `f32` in `[0,1]`, length `C*H*W`.
    fn step(&mut self, action: u32) -> Vec<f32>;
    /// Diffusion-sampler quality knob (number of function evaluations).
    /// Models without an NFE concept ignore it; default is a no-op.
    fn set_nfe(&mut self, _n: u32) {}
}

/// Deterministic, GPU-free test model: a bright 8x8 square moving over a
/// fixed gradient background, 64x64 RGB, 5 actions (noop/W/A/S/D).
pub struct FakeWorldModel { /* private: px: u32, py: u32 */ }

impl FakeWorldModel {
    /// Starts at square position (px, py) = (0, 0) (as if reset had hashed
    /// to 0). Usable without calling `reset`.
    pub fn new() -> Self;
}

impl Default for FakeWorldModel { /* = new() */ }

impl WorldModel for FakeWorldModel { /* per §3–§5 */ }
```

The trait must be OBJECT SAFE: `Box<dyn WorldModel>` must compile and be
callable (no generic methods, no `Self`-returning methods, only
`&self`/`&mut self` receivers).

## 3. FakeWorldModel — constants and state

| Constant | Value |
|---|---|
| `C, H, W` | 3, 64, 64 (`frame_shape() == (3, 64, 64)`) |
| frame length | `C*H*W = 3*4096 = 12288` |
| `num_actions()` | 5 |
| square side `S` | 8 |
| square value | `1.0` (all three channels) |

Actions (index → meaning → position delta `(dx, dy)`):

| action | key | dx | dy |
|---|---|---|---|
| 0 | noop | 0 | 0 |
| 1 | W (up) | 0 | −1 |
| 2 | A (left) | −1 | 0 |
| 3 | S (down) | 0 | +1 |
| 4 | D (right) | +1 | 0 |

Mutable state is exactly the integer square position `(px, py)`,
`px in 0..64`, `py in 0..64` — the top-left corner of the square. There is NO
floating-point state carried across steps (this is what makes bitwise
determinism trivial, §7).

## 4. Exact math

### 4.1 reset — seeding by FNV-1a hash of the context

`reset(ctx_frames, ctx_actions)` computes a 64-bit FNV-1a hash `h` over the
following byte stream (little-endian throughout, lengths prepended for
domain separation so `([], [7])` and `([f32::from_bits(7)], [])` differ):

1. `(ctx_frames.len() as u64).to_le_bytes()` — 8 bytes
2. for each `f` in `ctx_frames`: `f.to_bits().to_le_bytes()` — 4 bytes each
   (bit pattern, NOT value: NaNs are fine, `-0.0` and `+0.0` differ — documented)
3. `(ctx_actions.len() as u64).to_le_bytes()` — 8 bytes
4. for each `a` in `ctx_actions`: `a.to_le_bytes()` — 4 bytes each

FNV-1a 64: `h = 0xcbf29ce484222325`; per byte `b`:
`h = (h ^ b as u64).wrapping_mul(0x100000001b3)`.

Then:

```text
px = (h        & 63) as u32        // low 6 bits
py = ((h >> 32) & 63) as u32       // bits 32..38
```

### 4.2 step — move, then render

`step(action)`:

1. `assert!(action < 5)` — see §6 edge cases.
2. Move with wrap-around (all arithmetic mod 64; in u32 code use
   `(px + 63) % 64` for a −1 move so nothing underflows):
   `px ← (px + dx + 64) mod 64`, `py ← (py + dy + 64) mod 64`.
3. Render and return the frame at the NEW position (move-then-render: the
   frame returned by `step` already reflects `action`).

### 4.3 Rendering (pure function of `(px, py)`)

For `c in 0..3`, `y in 0..64`, `x in 0..64`, output index
`i = c*4096 + y*64 + x`:

```text
in_square(y, x) = ((x + 64 - px) mod 64) < 8  AND  ((y + 64 - py) mod 64) < 8
```

(i.e. the square covers columns `{px, px+1, …, px+7} mod 64` and rows
`{py, …, py+7} mod 64` — the FOOTPRINT ITSELF WRAPS across the right/bottom
edge, appearing split on both sides.)

```text
frame[i] = 1.0                      if in_square(y, x)
         = bg(c, y, x)              otherwise

bg(0, y, x) = x as f32 / 63.0       // R: left→right ramp 0..=1
bg(1, y, x) = y as f32 / 63.0       // G: top→bottom ramp 0..=1
bg(2, y, x) = 0.25                  // B: constant
```

All values lie in `[0, 1]`. Distinguishability invariant: the blue channel is
`1.0` exactly on the square footprint and `0.25` everywhere else, so two
frames rendered at different `(px, py)` ALWAYS differ (the 8x8 footprint,
64 pixels, cannot coincide for distinct wrapped positions), and the square is
recoverable from the frame — `set(f) = { (y,x) : f[2*4096 + y*64 + x] == 1.0 }`
has exactly 64 elements.

## 5. Hand-computed reference values

### 5.1 Seed hash, Case A — empty context: `reset(&[], &[])`

Byte stream = 16 zero bytes (two u64 zero lengths). Each FNV step is
`h = (h ^ 0) * 0x100000001b3 mod 2^64`, i.e. 16 multiplications from the
offset basis. First two and final steps (full chain reproducible from §4.1):

```text
h0 = 0xcbf29ce484222325
after byte  0: 0xaf63bd4c8601b7df   (= h0 * 0x100000001b3 mod 2^64)
after byte  1: 0x08328807b4eb6fed
…
after byte 15: 0x88201fb960ff6465   = h
px = h & 63          : 0x65 = 0b110_0101 → 0b10_0101 = 37
py = (h >> 32) & 63  : low byte of 0x88201fb9 is 0xb9 = 0b1011_1001 → 0b11_1001 = 57
```

⇒ after `reset(&[], &[])`: `(px, py) = (37, 57)`.

### 5.2 Seed hash, Case B — `reset(&[0.5], &[3])`

`0.5f32.to_bits() = 0x3F00_0000` → LE bytes `00 00 00 3F`. Full stream
(24 bytes, hex): `01 00 00 00 00 00 00 00 | 00 00 00 3F | 01 00 00 00
00 00 00 00 | 03 00 00 00`. Checkpoints:

```text
after the 8 frame-length bytes : 0x89cd31291d2aefa4
after the 4 f32-bit bytes      : 0x5f245439c2426e29
after all 24 bytes             : h = 0x339bdfb58ed81f5b
px = 0x5b & 63 = 0b101_1011 → 0b01_1011 = 27
py = (h >> 32) & 63: low byte of 0x339bdfb5 is 0xb5 → 0b11_0101 = 53
```

⇒ after `reset(&[0.5], &[3])`: `(px, py) = (27, 53)`.

### 5.3 Motion and wrap-around (from Case A, `(37, 57)`)

```text
step(0)  (noop) : (37, 57)
step(4)  (D)    : (38, 57)          37+1 = 38
then step(1) (W): (38, 56)          57-1 = 56
Fresh reset A, then 7 × step(3) (S): py = (57+7) mod 64 = 64 mod 64 = 0
                                     → (37, 0)      ← bottom→top wrap
Fresh reset A, then 38 × step(2) (A): px = (37−38) mod 64 = −1 mod 64 = 63
                                     → (63, 57)     ← left→right wrap
From new() (0,0), step(1) (W)       : py = (0−1) mod 64 = 63 → (0, 63)
From new() (0,0), step(2) (A)       : px = 63 → (63, 0)
```

### 5.4 Pixel values (Case A after one `step(0)` — position `(37, 57)`)

Note rows 57..=63 AND row 0 belong to the square (footprint wraps:
`(0 + 64 − 57) mod 64 = 7 < 8`). With `i = c*4096 + y*64 + x`:

```text
frame[11877] = frame[2*4096 + 57*64 + 37]   (B at square origin (y=57,x=37))
             = 1.0
frame[8236]  = frame[2*4096 +  0*64 + 44]   (B at (y=0,x=44): y-off (0−57)%64=7<8,
             = 1.0                           x-off 44−37=7<8 → wrapped square)
frame[8300]  = frame[2*4096 +  1*64 + 44]   (y-off (1−57)%64 = 8 ≥ 8 → bg B)
             = 0.25
frame[21]    = frame[0*4096 +  0*64 + 21]   (x-off (21−37)%64 = 48 ≥ 8 → bg R)
             = 21.0f32 / 63.0f32 = 0.33333334f32   (nearest f32 to 1/3)
frame[4741]  = frame[1*4096 + 10*64 + 5]    (bg G at y=10)
             = 10.0f32 / 63.0f32 = 0.15873016f32
frame[0]     = frame[0*4096 + 0*64 + 0]     (bg R at x=0, off-square)
             = 0.0
```

### 5.5 From `new()` (position `(0,0)`), first `step(0)`

```text
frame[8192]  = B at (0,0)      = 1.0        (in square)
frame[8192 + 7*64 + 7] = B(7,7) = 1.0       (square is 0..=7 inclusive)
frame[8192 + 8*64 + 8] = B(8,8) = 0.25      (first off-square diagonal pixel)
frame[63]    = R at (0,63)     = 63/63 = 1.0  (bg may equal 1.0 in R/G — only
                                               the B channel identifies the square)
```

## 6. Edge cases (normative)

1. `step(action)` with `action >= num_actions()` (i.e. ≥ 5) PANICS
   (assert). It never wraps or clamps the action.
2. `reset` accepts ANY slice lengths, including both empty (Case A) —
   `ctx_frames` need not be a multiple of `C*H*W`; the fake only hashes bits.
3. Context values are hashed by BIT PATTERN: NaN payloads are legal input;
   `-0.0` vs `+0.0` give different seeds (documented on the trait impl).
4. Wrap-around is toroidal in BOTH movement (§5.3) and rendering footprint
   (§5.4): a square at `(63, 57)` paints columns `{63, 0..=6}`.
5. `step` returns a FRESH `Vec<f32>` (length exactly 12288) each call — no
   aliasing of internal buffers.
6. `set_nfe` on `FakeWorldModel` is the trait default (no-op); calling it
   must not change subsequent frames.
7. `new()`/`Default` state is `(0, 0)` and is stepable without `reset`.

## 7. Determinism (normative)

- `FakeWorldModel` carries only integer state `(px, py)`; every emitted f32
  is computed fresh from integer coordinates by a single IEEE-754 f32
  division (`x as f32 / 63.0`) or is a literal (`1.0`, `0.25`). No
  accumulation, no RNG, no time, no platform-dependent ops.
- Therefore: identical `(ctx_frames, ctx_actions)` to `reset` followed by an
  identical action sequence produces BYTE-IDENTICAL frames
  (`f32::to_bits` equality element-wise, not approximate equality) — across
  runs and across machines.
- Tests MUST compare bitwise (`to_bits()` or exact `==`), never with a
  tolerance.

## 9. Acceptance criteria

Tests (written from THIS spec, in `crates/wm-core`, filter `wm_trait`/crate
`brain-wm-core`) must cover at least:

1. **Object safety**: `let mut m: Box<dyn WorldModel> = Box::new(FakeWorldModel::new());`
   compiles; `frame_shape()`, `num_actions()`, `reset`, `step`, `set_nfe`
   callable through the box; shape is `(3, 64, 64)`, actions `5`.
2. **Determinism (bitwise)**: two fresh models, same `reset(ctx, actions)`
   (use Case B inputs) and the same action sequence
   (e.g. `[4,4,1,0,3,2,2,2]`) → every returned `Vec<f32>` is bitwise
   identical between the two runs. Also: `reset` twice on ONE instance
   re-produces the same first frame.
3. **Seed math**: Case A and Case B positions verified via §5.4-style pixel
   probes (blue channel `1.0` at the predicted square origin, `0.25` just
   outside it).
4. **Action consequence**: from a common reset, `step(a)` for each
   `a in 0..5` on 5 fresh instances → all 5 frames pairwise different, and
   each non-noop frame differs from the noop frame.
5. **Frame bounds & length**: every value in `[0.0, 1.0]`, `len == 12288`,
   for several steps including wrapped positions.
6. **Wrap-around**: the §5.3 cases (left from x=0 → 63, up from y=0 → 63,
   down across y=63 → 0) verified via blue-channel probes; plus a rendering-
   footprint wrap check (§5.4: `frame[8236] == 1.0`, `frame[8300] == 0.25`).
7. **Panic path**: `step(5)` panics (`#[should_panic]`).
8. **set_nfe inert**: `set_nfe(1)` vs `set_nfe(64)` (or none) → identical
   subsequent frames.

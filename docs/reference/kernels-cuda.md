# Native CUDA kernel catalogue

Every hand-written CUDA kernel brain ships, generated directly from the
registry that defines them - nothing here is inferred or hand-maintained.
Regenerate with `make cuda-table`; `make cuda-table/check` fails the build if
this page has drifted from that registry, or if a kernel source file sits in
the tree unregistered.

This is the **native** catalogue. The portable one - the WGSL kernels every
backend runs, and the reference every other implementation is checked
against - is the [kernel catalogue](kernels.md). The two are deliberately
separate registries with separate gates: a WGSL kernel is validated by
compiling it on the test device and cross-checking five metadata fields
against the shader text, and none of those checks can read CUDA C++.

A kernel appearing here does not make it the one that runs. Which
implementation answers an operator is decided per dispatch, against the
device capability the driver was queried for, and recorded - so a portable
kernel serving an operator a native one was expected to serve is a reported
fact, not a silent slowdown.

Every column is stated by the kernel's own registry entry in `crates/kernels-cuda` - nothing here is inferred. `make cuda-table` regenerates this block; `make cuda-table/check` fails when a kernel source is not registered, or when this table has drifted from the registry. Edit the registry, never the row.

**No hand-written CUDA kernel ships yet.** The native CUDA backend enumerates devices and states its tier policy, but cannot yet compile or launch anything, so there is no kernel to list. This page, its registry and its gate exist first on purpose: the first kernel to land arrives into something that checks what it claims about itself.

**tier** - `tuned` is hand-written for this backend, optionally specialised to a queried device capability. It is the only tier a file in this tree can claim: a `generated` kernel is emitted from the portable WGSL reference at run time and has no source file here, and the `reference` tier IS that WGSL.

**min cc** - the lowest compute capability the kernel's own TEXT is valid on, decided by the instructions it uses. It is not a statement about any card: which kernel a device gets is resolved at run time against the capability the driver was asked for, highest eligible floor first.

# served-training

Scope: Training as a job of the serving process (`crates/trainjob`): `brain/train`, its artifact store, scheduling with serving residents, the job event stream.

## Done

- `brain/train` / `train`: supervised (`sft`) and policy-gradient (`policy_gradient`, teacher contexts included) fine-tuning of a chat LoRA through `brain::ChatFineTune`, the same settings the SDK takes; qwen35 first, qwen3 for the supervised objective (the policy-gradient objective is qwen35 only, as in the SDK). `brain serve --training [--artifact-store DIR]`.
- Datasets and the starting adapter by input blob (D-Bus file descriptors) or by blake3 digest in the operator's artifact store (`--artifact-store`); the adapter is published to the store and named by digest, and returned as an output blob when `return_adapter` is set. A digest is 64 lowercase hex digits and the server copies the file into the job's private directory while verifying it. No caller-supplied path exists.
- Progress: one `step` frame per optimiser step (loss, lr, grad norm, seconds; `pg` with clip fraction, KL, importance ratio, advantage statistics and the scoring seconds for a policy-gradient run) over D-Bus `Subscribe` progress frames and over HTTP `GET /v1/jobs/{id}/events` (SSE, `Last-Event-ID` replay of the last 4096 frames, 8 followers per job). `Cancel` / `DELETE /v1/jobs/{id}` stop the run at the next step.
- Scheduling (`residency::ResidentModel::{transient, check_job}`, `Executor::check_job`): the run reserves its footprint (`ChatFineTune::footprint`: base at its tier, activations of one `max_block` row, adapter and optimiser state, a margin), takes the card with the most room or evicts idle serving instances on the best candidate, never an instance a request is running on, waits for the admit deadline and is then refused (429); a run larger than the largest card is refused at the door; the reservation returns when the run ends. One run per card.
- A call a model refuses at the door (`check_job`) is a 400 on HTTP and a bus error, before a job exists. `/v1/run` and `/v1/jobs` bodies refuse unknown fields.
- Tests: `crates/trainjob` (store, request, door refusals, real runs, scheduling, HTTP, D-Bus), `crates/apiserve/tests/capabilities.rs` (event stream), `tests/e2e/api_conformance.bats` (flags, auth, refusals), `crates/residency` (transient, check_job).

## Served-only consumers (lane api, 2026-11-13)

- [x] `objective: dpo` on `brain/train`: `brain::PreferenceFineTune` placed on the scheduler's card (`placed`, architecture detected from the base's config, the frozen base's tier chosen for the card as `ChatFineTune` does), the same request validation, limits, door checks and artifact-store transport; the footprint is sized to the two rows of a pair (`Objective::rows_per_step`). Tested on the CPU toy `qwen3`: the loss starts at ln 2 and falls, the tuned margin is positive, bad pairs are refused by record.
- [x] `full_train` and `merge` actions of `brain/train` (`crates/trainjob/src/consolidate.rs`): `brain::ChatFullFineTune` and `brain::merge_adapter` placed on the scheduler's card (`placed`; architecture detected from the base's config; `ChatFullFineTune::footprint` for admission: fp32 weights and gradients plus activations and a margin, a model not a measurement), the checkpoint published to the artifact store as a manifest of per-file digests and optionally installed as `local/<name>`; a merge reserves host memory only and takes no card. Open: a qwen35 merge (its export may not fold an adapter), a checkpoint larger than the model store's free disk is only discovered when it is written.
- [x] `check_dataset` action of `brain/train` (`crates/trainjob/src/dryrun.rs`, `brain::dataset_report::check_dataset`): the whole file against a base's tokenizer and template with every refusal listed, per-example token and supervised-token distributions, examples past `max_block`; chat records and preference pairs; host work, no card.
- [x] `check_dataset` pages: `per_record` (with `offset`, `limit`) lists, for each record of the page, `[line, tokens, prompt, trained, examples]` (tokens of its longest example, split into unsupervised and supervised, a teacher's rendering counted in `tokens`) and, in `per_record_refused`, each refused record with its rule and field; at most 200000 records per page with `per_record_next` the next offset (2026-11-17: offset counts valid and refused records alike, refusals and the prompt/trained split added), so a client that sizes and packs records needs no tokenizer of its own. Tests: `dataset_report` unit tests (counts equal the trainer's own reader over the contract fixtures), `trainjob` `dryrun`, `http` and `dbus` (HTTP and bus return what the executor returns; an over-cap `limit` is refused). Speech has no job: the synthesizer's policy training (`TtsPolicy` rollout and update) is a stateful in-process loop of the SDK, not a request.
- [x] Audit of the API surface for this lane (api-security.md): every new route and action is behind the key and the training role/flag (`/v1/devices` and `/v1/audio/speech` behind the key like every route, `/v1/devices` and the speech route reporting no path, address or UUID); every param is typed with `deny_unknown_fields` and range-bounded by its spec (a dialect route that reaches an action now validates it against that action's `ActionSpec`: embeddings, speech); no param names a file of the host (`install_as` is one plain `local/<name>`, parsed by `ModelRef`, refused when taken); a checkpoint is published only by digest from a job's private directory; D-Bus carries the new actions through `Subscribe` unchanged. Tests: `crates/trainjob/tests/it/{door,consolidate}.rs`, `crates/apiserve/tests/{capabilities.rs,it/speech.rs,it/api.rs}`, `tests/e2e/api_conformance.bats`.

## Adapter hot-load (lane rollout, 2026-11-13)

- [x] `--serve-adapters DIR`: every `*.safetensors` adapter under a directory is offered as a model of its own and the offered set follows the files (appear, renamed over, disappear) with no restart; symlinks, hidden files and other names ignored, depth 4, 1024 files, each file read once, size-capped and verified against the base. Gated on the CPU in `crates/cli/src/adapter_directory.rs` (follow, refuse without replacing what serves, id moves).
- [x] `--serve-adapters` over several served bases (2026-11-18): each adapter binds to the served base its card names (base id, else the base digest it records; verified by digest as before), adapters of several bases are served at once, and one whose base is not served is refused naming it (`llmserve::adapter_release::{verify_adapter_among, BindError::BaseNotServed}`); it bound every adapter to the one base `Host::pick` chose, so a store serving Qwen3-4B and Qwen3.8-27B refused the 4B's adapters. Test `each_adapter_rides_on_the_base_its_card_names` (two toy bases, CPU).
- [x] A policy version per adapter id (`AdapterIdentity::version`): 1 for the first release, +1 for a replacement with different weights, kept across withdrawal; in `/v1/models` (`adapter.version`), in every reply's `brain.adapter` and in the policy trace's `policy.adapter`. A refit never reads the previous release's prefix-cache entries (one namespace per release digest): `a_refit_adapter_never_reads_the_previous_releases_cached_prompts` (`crates/catalog/tests/it/multi_adapter.rs`).
- [x] `--adapter-rank-cap` defaults to 32; a refusal names the cap to restart with. The cap is fixed when the engine is built (the bank's buffers are bound into recorded tapes), so an adapter above it cannot be hot-loaded.
- [x] Real-weight check (Qwen3.8-27B-FP8, one GH200, 2026-11-13): three rank-32 all-target adapters hot-loaded onto the running server by renaming files into the `--serve-adapters` directory (listed with `version` at once, served concurrently in one batch under their own ids), a `brain/train` job admitted at once after ~600 adapter requests (knowledge 438, the stall does not reproduce).
- [ ] The adapter bank's decode cost on the 27B at 8/32/64 rows is measured (knowledge 444: -50 %, -61 %, -66 % tokens/s with every row on one adapter, 13/26/47 ms extra per step) and the cause is profiled (the row-wise `lora_xa_rows` / `lora_delta_rows_multi` re-read the adapter for every row, L2-bound); a row-tiled kernel variant (`KernelVariant::RowTiled`, one-slot banks, from 2048 output pairs) landed and moves it to -53 / -55 / -63 % (knowledge 449); the launch-bound remainder needs a fused or library-GEMM design.
- [ ] At `--max-batch 64` the 27B on one 96 GB card needs `--reserve-gb 16`; at the default the graph launch runs out of memory and the model goes unservable (knowledge 445).

## Admission contract (2026-11-14)

- [x] A run is guaranteed a card under any request traffic (`residency::contract`): once it has waited `--train-max-wait-ms` (default 60 s) the cards it could use are held for it (new requests go elsewhere, batches on held cards take no late requests), and the hold ends when the run starts, is cancelled or is refused. Bound: that wait plus the longest request already running on a held card. Tests: `crates/residency/tests/it/admission.rs` (a run admitted within 1 s under traffic that keeps a full batch queued; it waited 3 s, the whole traffic, before), the exhaustive model `crates/residency/tests/it/fairness_model.rs` (adversarial arrivals and scheduler choice, six wiring mutations caught).
- [x] Every queued job, a run included, has a queue deadline inside the scheduler (`--queue-deadline-ms`, default 31 min), honoured at the instant it passes and in a running batch's inbox too; the job is answered with a `timeout` error naming the flag and its hold is released.

## Models from nothing (2026-11-16)

- [x] `init_model` (`crates/trainjob/src/create.rs`, `brain::ModelInit`): a byte-level BPE vocabulary learned on a corpus with declared special tokens, a chat template checked against the training and serving contract, a seeded random checkpoint of a declared config of any architecture whose `ChatTrainer` declares `FROM_SCRATCH` (ouro, qwen3); host work, parameter count bounded at the door (`create::MAX_PARAMS`).
- [x] `pretrain` (`crates/trainjob/src/pretrain.rs`, `brain::Pretrain`): raw-text causal LM of every weight through the family's full-parameter entry (windows of the separator-joined document stream, every position supervised), held-out `eval_loss` on the step frames; reserves the full-parameter footprint of one micro-batch.
- [x] `resume_key` on `init_model`, `pretrain`, `full_train` (`crates/trainjob/src/runs.rs`): durable run record and exact fit state under `<store>/.runs/<blake3(key)>/`, flock while running, identity = blake3(action, params less the resumption settings, blob digests), continued runs end at the straight run's weights, completed runs answer their recorded result, a damaged state or another run's key is refused (tests `crates/trainjob/tests/it/resume.rs`).
- [x] API audit for these actions (api-security.md): every param typed and bounded by its spec (a JSON document param at most 64 KiB, `deny_unknown_fields` inside), no path param (corpus and data by digest or attached blob, `install_as` and `resume_key` plain names that cannot spell a path), training-marked and behind the training role like every `brain/train` action; tests `crates/trainjob/tests/it/{create,pretrain,resume,door}.rs`.
- [x] `resume_key` / `checkpoint_every` on the adapter action `train` (2026-11-17), every objective (sft, policy_gradient, dpo): the same run record and lock (`crates/trainjob/src/runs.rs`), the training state at the run's `state.safetensors` through `ChatFineTune::resume_state` / `PreferenceFineTune::resume_state`, kept evaluation adapters under the run's `evaluations/`; a resumed run publishes the uninterrupted run's adapter byte for byte, a completed one answers its recorded result (adapter and record fetched back from the store with `return_adapter`). ## Open

- Multi-card runs: the qwen35 trainer is one card per run; a run that needs two cards (a bf16 27B on 80 GB cards) is refused with what it needs. The pipelined qwen3 trainer could be placed over several cards through `register_multi`.
- The footprint is a model (base bytes by tier, calibrated activations, a margin), not a measurement; a first run on a new base should be watched against `nvidia-smi`, and the estimate corrected if it is off.
- Real-weights runs of Qwen3.8-27B-FP8 through the service (policy gradient, rank 16, fp8 base, 8 records a step, 2026-11-12, knowledge #440) have run at lr 1.2e-5 to 3e-5, every one with `behaviour: start_of_run_proxy`: no serve-versus-train numerics measurement existed. `brain finetune --policy-gradient --numerics-gate` (SDK: `PolicyGradientConfig::numerics`) is that gate, run so far on Qwen3-4B (#446). The 27B's served engine (the FP8 release resident) returns `policy_trace` and declares `score` (2026-11-18; its trace reproduces the decode-time log-probabilities of an untruncated draw within 1e-5 on the CPU fixture, `crates/qwen35/tests/hf_fp8_score.rs`); the gate on its real weights ran 2026-11-18 (#446: mean gap 0.019, sequence ESS 0.4-0.6 at int8 or f32 K/V; the trace itself differs from the decode-time log-probabilities by 0.018 a token on the card). The tests of the service itself use a toy `qwen35` on the CPU backend.
- The `brain/train` action takes the step guard and the clip-higher and importance settings (`max_step_kl`, `max_step_grad_norm`, `clip_eps_high`, `importance`) but not the numerics gate, which is a `brain finetune` run (no update, nothing to publish).
- The policy gradient's reported KL (and the step guard reading it) is the importance-weighted k3 since 2026-11-17 (knowledge #509: the plain k3 read 1e7 where the divergence was 0.1 once a drawn token had moved 17 nats); the KL term of the loss is still the plain k3, whose gradient weight `kl_beta * (pi_ref / pi - 1)` is unbounded off-policy. Real-weight runs with recorded `policy_trace` log-probabilities have not been repeated since.
- The per-step PG series rides D-Bus progress frames, which are droppable; the complete series is the `record` blob.

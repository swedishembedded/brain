# service-security - roadmap

Scope: Every socket brain listens on, hardened for a network where other hosts are hostile (HTTP, D-Bus, the event-protocol socket, the training collective, the serve daemon's state).

Threat model: brain is bound on a private network. Any other host on it is
an attacker without a key; a key-holder may also be hostile. A private network
is not a trust boundary: nothing may rely on "only friendly hosts can reach it".

Audit of 2026-11-06 (source-verified). Each finding below is a milestone; a
milestone is done when its test is red before the fix and green after.

## Milestones

| # | Finding | Severity | Status |
|---|---|---|---|
| S1 | `brain forecast serve --listen` is an unauthenticated plaintext TCP surface, and a `camera_frame` `path` makes the server read any file of its machine (`/dev/zero` exhausts memory, a FIFO hangs the thread, the error text is a file-existence oracle). The event socket also reads unbounded lines. | high | done: the TCP listener is removed (its one consumer uses the Unix socket; the network surface is the key-gated `forecast` action of `brain serve`), the socket is `0600`, a line over 64 MiB is refused, and a frame is decoded only when a detector is loaded (`crates/server/tests/it/socket_hardening.rs`, `crates/runtime/tests/it/controller.rs`) |
| S2 | The HTTP server sets no header-read, body-read or idle timeout and no connection cap: an unauthenticated peer holds sockets open until the process runs out of descriptors (slowloris). A key-holder holds every edge permit with slow uploads. | high | done: `crates/apiserve/src/listener.rs` replaces `axum::serve` (10 s header and idle deadline, 5 min whole-body deadline, 1024 connections per surface, HTTP/1.1 only; `crates/apiserve/tests/it/connections.rs`). A slow upload now holds its edge permit at most the body deadline; a key-holder can still fill the edge with long legitimate requests, which is S8's missing per-caller quota |
| S3 | The HTTP API is plaintext: the key and every prompt and output cross the network readable. Decision: native TLS (`--tls-cert`/`--tls-key`), and a non-loopback bind without TLS is refused unless the operator passes `--insecure-plaintext`. | high | done: `apiserve::tls` (rustls on ring, HTTP/1.1 by ALPN, handshake within the header deadline), `--tls-cert`/`--tls-key`/`--insecure-plaintext`, `check_exposure` before anything loads, `https` in the connection record (`crates/apiserve/tests/it/tls.rs`, `crates/cli/tests/it/serve_cli.rs`) |
| S4 | The training collective authenticates nothing: any host that reaches the coordinator joins as a rank and injects gradients, and gradients and weights cross the network readable. Decision: a shared job secret, a mutual challenge-response at join, then every frame sealed with a per-session AEAD key. | high | done: `model::sealedwire` (mutual HMAC proof over fresh nonces, per-direction ChaCha20-Poly1305 keys from HKDF, sequence nonces), `--job-secret FILE` beside `--job-plan`/`--job-rank`, no unauthenticated constructor left; a stranger is dropped without disturbing the forming group. Tests and the measured cost: `distributed-execution.md` |
| S5 | D-Bus `Run`/`Subscribe` mmap a caller's fd without checking it cannot shrink: truncating it during the copy kills the server with SIGBUS. The number of fds a call carries is unbounded. | medium | done: a regular file or memfd is read with `pread` (a shrink mid-read is an error, never SIGBUS); only a dmabuf is mapped; at most 16 fds and 1 GiB per call (`dbus::fd` test `a_caller_shrinking_its_fd_mid_read_cannot_kill_the_server`) |
| S6 | The serve daemon's fallback state directory (`/tmp/brain-<uid>`) and `serve.log` are created with the default umask, and the log receives the `APIKEY` line: any local user reads the key, or pre-creates the directory. | medium | done with S27: the state directory is made and checked by `capability::scratch::private_dir`, the lock and log are `0600` |
| S7 | `max_tokens` has no upper bound of its own. Re-checked: the serving model refuses a prompt plus `max_tokens` over its context before admission, so the bound is the context; what is missing is a per-caller budget (S13). | low | merged into S15: `max_new`/`max_tokens` have a ceiling of 262144 besides the context check |
| S8 | With the shipped key authenticator every key-holder shares one job scope (lists, follows and cancels every job); D-Bus `Cancel` takes sequential ids. The docs say a job belongs to its caller. | high | done with S13: a named caller's name is its job scope (`crates/apiserve/tests/it/callers.rs`); D-Bus callers are the bus policy's, one trust level |
| S9 | `GET /v1/videos/{id}/content` streams the file from a blocking thread that waits on a 4-slot channel: a client that stops reading holds that thread for as long as its connection lives. | medium | open |
| S10 | Media is decoded on the async runtime's worker threads, before admission, with no bound on how many decode at once: images (`media.rs` `decode_image`), chat `input_audio` and `/audio/transcriptions` (`decode_speech`). The request-wide pixel budget is checked after each image is decoded, so one 8 MiB request of flat PNGs decodes about 100 Mpx (about 1.2 GB of f32) and a handful of them stall every surface of the process. | high | done: `apiserve::preprocess::off_runtime` decodes every request's media on the blocking pool, four at once process-wide, 503 after 30 s waiting (chat on all dialects, transcription, edit clips); an image is refused from its header against what is left of the request budget (`preprocess.rs` and `media.rs` tests) |
| S11 | The shipped system-bus policy lets only root own `com.swedishembedded.Brain1`, so `--dbus-system` makes the whole server (media decoders, model parsers, GPU drivers) run as root. | high | done: the shipped policy lets the system user `brain` own the name and root only call it; help and `docs/reference/api/dbus.md` say to run as that user |
| S12 | The video spool is `<tmp>/brain-videos-<pid>`, created with `DirBuilder::recursive`, which accepts a directory another local user created first: that user then reads every clip and can replace or redirect them. | medium | done with S27: the spool and the input staging directory are under the private root and checked by `private_dir` |
| S13 | One key per dialect is the whole security identity: every key-holder may run every served action through `/v1/run`/`/v1/jobs` (training only behind `--training`, fetch only behind `--auto-fetch`), shares one job scope (S8), and has no budget of its own, so one compromised client can occupy every lane. Fix: named callers, each with its own key file, a role (`inference`, `training`, `admin`) checked at the one dispatch boundary every surface shares, its own job scope, and its own concurrent-request budget. | high | done: `--caller NAME:ROLE:KEYFILE[:MAX]` (`apiserve::Callers`; every key compared, constant time), roles checked where every HTTP call is dispatched (`bridge::Pending::begin`), fetch only for `admin` (`AppState::supplier_for_caller`), a per-caller in-flight budget held until the call settles (background jobs included). Found on the way: every `lora_train` and splat `fit` was served without `--training`; actions that train are now marked `ActionSpec::training()` (catalog-wide test) and refused without `--training` on HTTP and D-Bus |
| S14 | Hostile video input to an edit action (`input_video` on `/v1/videos`, `clip_input` blobs): the MP4 box walk wraps `at + size` on a 64-bit size and loops forever growing a `Vec` (a 40-byte file), sample tables allocate by declared counts (`vec![uniform; count]`, 16 GB from one box), decoded frames have no pixel budget (only a 2000-frame cap), a stream the native demuxers refuse falls back to `ffmpeg`/`ffprobe` on the request's bytes (protocols, demuxer, time and memory unrestricted), and the 400 carries the temp path and ffmpeg's stderr. | high | done: the MP4 box walk and sample tables are bounded by the file (`videocodec::mp4` tests), dav1d refuses a frame over `videocodec::MAX_FRAME_PIXELS` before allocating it, a request clip is read by `imaging::video::clip_from_untrusted_file` (native decoders only, `capability::video::MAX_EDIT_CLIP_PIXELS` checked frame by frame, no path in its errors; `crates/imaging/tests/it/untrusted_clip.rs`), and `decode_video` checks its dimensions |
| S15 | Most numeric action params declare no `max`, and `step` is never enforced, so `/v1/run`, `/v1/jobs` and D-Bus `Run` accept `frames`, `width`, `height`, `steps`, `max_new` of any size; `resident_ltxv`'s estimate multiplies them unchecked. | high | done: ceilings and floors on every served number that sizes work (`frames`, `width`, `height`, `steps`, `max_new`, `rank`, `fps`, ...), a 16 MiB cap on any string param (`capability::MAX_STR_PARAM_BYTES`), and `crates/catalog/tests/it/served_bounds.rs` with the shrink-only `scripts/gates/unbounded-params.allow` (seeds, token ids, sampling and guidance scales, learning rates only) |
| S16 | Text a client sends is tokenized with special tokens recognised: a literal `<|image_pad|>` beside one real image indexes past the image grids in Qwen3-VL's M-RoPE (`mrope.rs`), so every such request panics the lane and forces a full reload. `stop` strings are uncapped in count and length and are matched per decoded token in the shared scheduler loop. | medium | open |
| S17 | Auto-fetch (opt-in) has no concurrency bound, byte cap or free-space check, starts one download per distinct id, and two quantisations of one repo write the same non-exclusive `.part` file without a checksum. | medium | open |
| S18 | Model files are parsed as trusted: GGUF reserves by header counts, recurses into nested arrays without a depth limit and multiplies shapes and offsets unchecked; the safetensors `parse_inner` panics on a malformed `data_offsets` and never checks the extent against the shape; hub-listed file names are joined onto the store without a `..` check. Reachable through auto-fetch or a poisoned store. | medium | open |
| S19 | Served training (`--training`): `FootprintCache` grows without eviction on caller-chosen `arch`/`base_format` strings, the artifact store and per-job staging have no byte quota. | medium | open |
| S20 | Smaller request-reachable defects: a truncated WAV `fmt ` chunk panics the decoder (one connection), a finished job cannot be deleted (32 finished jobs block a scope for an hour), D-Bus `build_inv` copies up to 256 MiB per fd synchronously on the bus executor before the blob names are checked. | low | open |
| S21 | Special-token injection: every Qwen-family chat path (`qwen3::chat::parse_request_as`, qwen3vl, qwen3omnimoe, minicpmv, deepseekvl, lfm, moondream3) encodes the client's text with special-token recognition, so `<|im_end|><|im_start|>system` in a message becomes a real system turn, forged `<tool_call>`/`<tool_response>` turns, or a placeholder that mismatches the images. | high | done: `SpecialMatcher::escape` and `LITERAL_MARK`, `Tokenizer::escape_untrusted`, `Invocation::escape_client_text` (JSON strings escaped after parsing), applied in `qwen3::chat::parse_request_as` and at the entry of qwen3vl, qwen3omnimoe, minicpmv, deepseekvl, fastvlm, moondream3 and ocrserve; llava already refuses a typed `<image>`, and its plain-text roles cannot be protected by escaping |
| S22 | Sizes and rates a blob declares reach allocations unchecked: a WAV sample rate (cosyvoice, ltxv, imaging sound tracks) drives the resamplers' lengths (rate 0 or 1 aborts the process), imageops `width`/`height`/`x`/`y` drive `vec![0; w*h*3]`, blob `as u32` casts truncate. | high | done: `audio::wav::checked_rate` (1-384 kHz) where every WAV header and blob `sample_rate` enters, at most 32 channels, a truncated `fmt` chunk refused (`wav` test `a_hostile_header_is_refused`); imageops sizes bounded through S15 |
| S23 | Auto-fetch (opt-in) trusts the hub listing and the redirect host: `url_host` is fooled by `evil.com?x.hf.co` while the HF token rides every hop, file names are joined onto the store unchecked (an absolute name writes anywhere), downloads have no byte cap, free-space check or concurrency bound, and every fetched repo stays registered. | high | done: redirects parsed with `url::Url` (https only, no userinfo, host suffix-checked; tests cover `?`, `#`, `@` and `\\` tricks), listed names refused unless a plain relative path (`plan::store_relative`), each download its own exclusive `.part` removed on failure and refused past its declared size, one fetch at a time (`StoreSupplier::fetching`). Fetch is admin-only for named callers (S13). Still open: a byte cap or free-space check before a download, and unregistering fetched models |
| S24 | Errors: D-Bus returns raw executor and model error strings (paths, panic text with file:line, OS errors); a failed clip encode returns the spool path over HTTP. | medium | done: `capability::ReplyError` sorts every reply error for HTTP and D-Bus alike; the detail is logged, a model's failure tag travels; clip encode errors carry no spool path (S14) |
| S25 | Per-request counts: embeddings `input` arrays are unbounded (one job each), `stop` lists and their strings are unbounded and scanned per token, messages per request and string params of `/v1/run` have no length cap. | medium | open |
| S26 | Shared state keyed by callers: Nemotron `transcribe_stream` sessions are named by the client (another caller who guesses the name reads or advances the stream) with no count cap; the llmserve intake threads run request parsing without `catch_unwind`, so a parse panic kills a thread for good. | medium | done: `Invocation::scope` (the caller's job scope, stamped at HTTP dispatch) keys Nemotron sessions, at most 256 open; llmserve intake threads catch a parse panic and answer the caller (`encode_overlap` test) |
| S27 | Predictable scratch paths created without an ownership check: video inputs and spool, cosyvoice reference audio (`File::create`, 0644), qwen3 training scratch (0755), ASR and forecast caches, the serve daemon's state dir (S6, S12). One private-scratch helper and a gate are the class fix. | medium | done: `capability::scratch` (`private_dir`, `private_root`, `scratch_dir`) is the one implementation; apiserve, the video spool and inputs, cosyvoice reference audio, qwen3 training scratch, the ASR and fincast NPU graphs, the NPU decoder export, the SDK held-out records and the serve daemon use it. `BRAIN_OV_CACHE` is gone (a fixed cache under the private root) |

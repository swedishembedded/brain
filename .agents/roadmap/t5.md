# t5 — roadmap

T5-XXL text encoder port (`crates/t5`), used to provide FLUX.1's text
conditioning: encoder-only, no decoder, no LM head, no tokenizer.

## Not yet done

- [ ] Sequence length 512 — the length FLUX.1 actually uses. Forward parity
      is currently gated only at length 128; at 512 the fp32 activations do
      not fit on one 24 GiB GPU, and the attention-score kernel's dispatch
      shape crosses into a code path that shorter sequences never exercise,
      so it needs its own verification pass.
- [ ] Backward pass / gradient check — no gradient oracle exists yet. It must
      be built at the small reference dimensions, not the full XXL
      dimensions, because at XXL a gradient check could pass while confusing
      head count with head width and still agree with a wrong backward.
- [ ] Serving surface — no `Provider`, no residency adapter, no `run_batch`,
      no D-Bus exposure, no CLI subcommand. `crates/flux1` declares a
      dependency on this encoder but does not yet call it.
- [ ] Tokenizer — not implemented; parity testing replays pre-tokenized
      reference input ids rather than tokenizing text.

The CPU backend's reduction order depends on Rayon's runtime work-splitting,
so its low-order output bits are not deterministic run-to-run — it cannot be
used as an exact numeric fingerprint the way the GPU path can.
